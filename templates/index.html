学習の進め方

  1. 体験する: 各画面の「入力例を入れる」「攻撃を試す」のボタンで、攻撃を実際に動かします。
  2. 確かめる: 「サーバー内部で何が起きたか」の青い枠で、サーバーが何を受け取り、何を確認しなかったかを見ます。
  3. 考える: 「ヒント」を見ながら自分で試し、「なぜ危険か / 本来どう直すか」と「本来の対策」のコードで、直し方を確認します。

おすすめの順序:

  1. 入力値の扱い: 1.1 SQLインジェクション → 1.2 OSコマンド → 1.3 パストラバーサル
  2. ブラウザが絡む攻撃(罠サーバーが必要): 1.5 XSS → 1.6 CSRF → 1.9 クリックジャッキング
  3. ログインと権限: 1.4 セッション管理 → 1.11 認可制御
  4. そのほか: 1.7 HTTPヘッダ → 1.8 メールヘッダ → 1.10 バッファオーバーフロー(解説のみ)

罠サーバー(別ポート 9090)は make up で一緒に起動します。体験で変えたデータは、下のボタンで戻せます。

第1章 ウェブアプリケーションのセキュリティ実装

  • 1.1 SQLインジェクション: ログイン / 商品検索
  • 1.2 OSコマンド・インジェクション: ping
  • 1.3 パス名パラメータの未チェック／ディレクトリ・トラバーサル: ファイル閲覧
  • 1.4 セッション管理の不備: ログイン / マイページ(罠ページは 127.0.0.1:9090/session/)
  • 1.5 クロスサイト・スクリプティング: 反射型 / 格納型(掲示板)(反射型の罠ページは 127.0.0.1:9090/xss)
  • 1.6 CSRF(クロスサイト・リクエスト・フォージェリ): ログイン / アカウント(罠ページは 127.0.0.1:9090/csrf/)
  • 1.7 HTTPヘッダ・インジェクション: リダイレクト
  • 1.8 メールヘッダ・インジェクション: お問い合わせフォーム
  • 1.9 クリックジャッキング: ログイン / 設定(罠ページは 127.0.0.1:9090/clickjack/)
  • 1.10 バッファオーバーフロー: 解説のみ(Go はメモリ安全な言語のため再現しない)
  • 1.11 アクセス制御や認可制御の欠落: ログイン / プロフィール / 管理画面
