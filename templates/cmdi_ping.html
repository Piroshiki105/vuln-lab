ヒント
  • シェルでは ; や && でコマンドを続けて書けます。
  • 127.0.0.1 の後ろに id や ls を続けるとどうなるでしょう?
  • $(...) や バッククォートも、シェルが先に評価します。
なぜ危険か / 本来どう直すか

入力値をシェルのコマンド文字列に連結すると、入力に含まれる ; && | $() などがシェルの構文として解釈され、攻撃者がサーバー上で任意のコマンドを実行できます。情報の窃取、ファイルの改ざん、サーバーの乗っ取りにつながります。

対策は次のとおりです。

  • シェルを経由しない: Go では exec.Command("ping", "-c", "1", host) のように、コマンドと引数を分けて渡す(sh -c を使わない)。
  • 入力の検証: ホスト名は許可リスト(英数字・.・- のみ等)で検証する。先頭が - の値はオプションとして解釈されるため拒否する。
  • そもそも外部コマンドを避ける: ライブラリ(net パッケージ等)で代替できないか検討する。
  • 権限の最小化: アプリの実行ユーザーの権限を絞る。
